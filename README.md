# โอมจ๋า (Ohmjaa)

เว็บสำหรับครูห้อง ม.2/3 ใช้ค้นหาข้อมูลนักเรียน บันทึกและติดตามพฤติกรรม สุ่มจัดกลุ่มนักเรียน จัดการข้อมูลกิจกรรมพิเศษ/ไซส์เสื้อ ดูรายงาน และพิมพ์เอกสาร A4

## ฟังก์ชันหลักของระบบ

1. **ภาพรวมและติดตามวินัย:** ดูสถิติพฤติกรรมและการทำเวรประจำวัน คำนวณวันเวรโดยอัตโนมัติ (ข้ามวันหยุดและเสาร์-อาทิตย์)
2. **ข้อมูลและประวัตินักเรียน:** ค้นหานักเรียนรายคน ตรวจสอบประวัติการทำเวร วันเวรประจำสัปดาห์ และคะแนนวินัย
3. **วงล้อสุ่มนักเรียน (Interactive Spin Wheel):** วงล้อหมุนสุ่มนักเรียนแบบ 60fps ฟิสิกส์ชะลอความเร็วสมจริง ปรับขนาดพอดีกับทุกหน้าจอและ HiDPI ข้อความอ่านง่ายไม่อยู่ในสภาพกลับหัว มีช่องค้นหาชื่อในวงล้อ พร้อมเสียงคลิกและเสียงฉลองชัยชนะ (Web Audio API) ตัดชื่อผู้โชคดีออก หรือคืนชื่อกลับเข้าวงล้อได้
4. **สุ่มจัดกลุ่ม (Random Group Generator):** แบ่งกลุ่มตามจำนวนกลุ่มหรือคนต่อกลุ่ม คละเพศชาย-หญิง สุ่มหัวหน้ากลุ่ม พร้อมคัดลอกส่งต่อและพิมพ์ A4
5. **ข้อมูลกิจกรรมพิเศษ & ไซส์เสื้อ (Class Activities & Sizes):** รวบรวมไซส์เสื้อ (S-4XL) สรุปยอดสั่งตัดเสื้ออัตโนมัติ เช็คการจ่ายเงิน และมอบหมายหน้าที่ในกิจกรรม (นักกีฬา, กองเชียร์, พาเหรด, สวัสดิการ ฯลฯ) พร้อมไดอะล็อกเลือกคอลัมน์และช่องเซ็นรับก่อนพิมพ์รายงาน A4 รูปแบบมาตรฐานโรงเรียน
6. **บันทึกวินัย & พิมพ์รายงาน A4:** บันทึกความผิด/คะแนนความประพฤติรายคนหรือแบบกลุ่ม พร้อมแอนิเมชั่นเวลาลบรายการ (Framer Motion) และพิมพ์เอกสารขนาด A4
7. **ประวัติและการแก้ไข (Audit Log):** บันทึกการแก้ไขข้อมูลเพื่อความโปร่งใสและตรวจสอบได้

## เริ่มใช้งานในเครื่อง

ต้องมี Node.js และ npm (แนะนำ Node.js 22 ขึ้นไปสำหรับ Supabase SDK ที่ติดตั้งอยู่)

```bash
npm ci
```

สร้าง `.env.local` ในโฟลเดอร์หลัก:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_PUBLISHABLE_OR_ANON_KEY
```

จากนั้นรัน:

```bash
npm run dev
```

เปิด `http://localhost:3000` หากไม่มีข้อมูลนักเรียนจาก Supabase หน้าแรกจะใช้ `src/data/students.json` เป็นข้อมูลสำรอง

## คำสั่งที่ใช้บ่อย

| คำสั่ง | ใช้ทำอะไร |
| --- | --- |
| `npm run dev` | เปิดเซิร์ฟเวอร์พัฒนา |
| `npx tsc --noEmit` | ตรวจ TypeScript |
| `npm run build` | สร้าง production build |
| `npm run start` | เปิด production build |

## ส่วนสำคัญของระบบ

- หน้าแรกอยู่ที่ `src/app/page.tsx` และ UI หลักอยู่ที่ `src/components/DisciplinaryApp.tsx`
- หน้าสุ่มจัดกลุ่มและกิจกรรมพิเศษอยู่ที่ `src/components/ActivitiesAndGrouping.tsx` และวงล้อสุ่มอยู่ที่ `src/components/SpinWheel.tsx`
- Supabase client อยู่ที่ `src/utils/supabase/`; การอ่านและแก้ไขข้อมูลที่ UI ปัจจุบันเรียกใช้อยู่ใน `src/app/actions.ts`
- แบบข้อมูลอยู่ที่ `src/types/penalty.ts` และ `src/types/activities.ts`; การคำนวณวันทำเวรอยู่ที่ `src/lib/choreSchedule.ts`
- รายงานในแอปใช้ `window.print()` เพื่อพิมพ์หรือเลือกบันทึกเป็น PDF จากเบราว์เซอร์; `html/report.html` เป็นหน้า HTML แยก
- SQL สำหรับตั้งฐานข้อมูลอยู่ใน `supabase/` อ่านไฟล์ migration และตรวจ policy ก่อนนำไปใช้กับฐานข้อมูลจริง

## ข้อควรรู้ก่อนใช้งานจริง

- หน้า `/login` ปัจจุบัน redirect ไป `/` และหน้า `/` ยังไม่ได้ใช้ `teacherActions.ts` เพื่อจำกัดข้อมูลตามบัญชีครู อย่าถือว่า UI ปัจจุบันมีการบังคับสิทธิ์ครูครบถ้วน
- วันหยุดโรงเรียนยังเก็บใน `localStorage` ของเบราว์เซอร์เครื่องนั้น วันเวรประจำสัปดาห์เตรียมให้อ่านจาก `student_weekly_duty` แล้ว โดยเว็บอ่านได้อย่างเดียว ผู้ดูแลฐานข้อมูลต้องตรวจและรัน `supabase/migration_student_weekly_duty.sql` แล้วเพิ่มวันเวรของแต่ละคนผ่าน SQL editor หรือช่องทางผู้ดูแลที่เชื่อถือได้ โค้ดนี้ยังไม่เพิ่มตารางเวรให้ใครโดยอัตโนมัติ
- ระบบคิดวันทำเวรโดยข้ามเสาร์–อาทิตย์และวันหยุดที่กรอกไว้ ระยะเวลาแบบเทอมหรือปีการศึกษายังไม่ถูกแปลงเป็นจำนวนวันอัตโนมัติ
- `@vercel/analytics` ติดตั้งเป็น dependency แล้ว แต่ยังไม่ได้วาง Analytics component ใน layout
